description: JOIN과 서브쿼리 방식의 차이점
JOIN 방식은 customer와 orders를 직접 연결하므로 두 테이블의 컬럼을 함께 조회하기 좋다.
예를 들어 고객명과 주문일, 주문상태를 한 번에 보고 싶을 때 적합하다.
서브쿼리 방식은 특정 조건을 만족하는 대상만 필터링할 때 읽기 쉽다.
현재 요구사항처럼 고객 정보만 필요하면 서브쿼리 방식도 충분히 명확하다.
하지만 주문 정보까지 함께 출력해야 한다면 JOIN 방식이 더 적합하다.

description: order_item.menu_id는 menu.id를 참조한다.
description: 현재 menu 테이블에 id=999인 메뉴가 없으므로 FOREIGN KEY constraint failed 에러가 발생한다.

query 2. 고치는 방법 1 - 존재하는 menu_id 사용
description: 이미 존재하는 menu_id=20을 사용하여 order_item 데이터를 입력

query 4. 테스트용 order_item 데이터 삭제
description: 다음 테스트를 위해 id=100인 order_item 데이터를 삭제

query 5. 삭제 결과 확인
description: id=100인 order_item 데이터가 삭제되어 조회 결과가 없어야 한다

query 6. 고치는 방법 2 - 부모 데이터 먼저 입력
description: order_item이 참조할 수 있도록 menu 테이블에 id=999인 부모 데이터를 먼저 입력

query 7. 부모 데이터 입력 결과 확인
description: menu 테이블에 id=999인 테스트 메뉴가 입력되었는지 확인
id   category_id  name         price  is_available
---  -----------  -----------  -----  ------------

query 8. 부모 데이터를 참조하는 자식 데이터 입력
description: menu_id=999가 menu 테이블에 존재하므로 order_item 입력이 가능하다

query 9. order_item 입력 결과 확인
description: id=100인 order_item 데이터가 menu_id=999를 참조하며 입력되었는지 확인
id   order_id  menu_id  quantity  unit_price
---  --------  -------  --------  ----------
100  1         999      1         5000      

query 10. 테스트용 order_item 데이터 삭제
description: 테스트 후 자식 데이터인 order_item을 먼저 삭제

query 11. 테스트용 menu 데이터 삭제
description: 자식 데이터를 삭제한 뒤 부모 데이터인 menu를 삭제

query 12. 테스트 데이터 삭제 결과 확인
description: id=100인 order_item과 id=999인 menu가 모두 삭제되어 조회 결과가 없어야 한다

description: FK 제약조건 정리
order_item.menu_id는 menu.id를 참조하는 FK이다.
존재하지 않는 menu_id=999를 order_item에 입력하려고 하면 참조 대상이 없기 때문에 입력이 막힌다.
이를 해결하려면 이미 존재하는 menu_id를 사용하거나, menu 테이블에 부모 데이터를 먼저 입력한 뒤 order_item에 자식 데이터를 입력해야 한다.
FK 제약조건은 잘못된 참조 데이터가 저장되는 것을 막아 데이터 정합성을 보장한다.
